# Research Capability Transfer

## 能力目标

让目标工程具备统一调研能力：先固定调研合同和证据等级，再按对象分支给出成熟度、风险、行动等级、刷新触发和沉淀落位。

## 可以吸收

- 聚合入口模式：把技术、产品、公司、行业、AI、PoC 和源码工程研究统一到一个 `research-capability` 总入口。
- 调研合同字段：对象、决策目标、关键问题、深度等级、证据计划、输出形态、不做项。
- 证据等级：L1 一手事实、L2 权威分析、L3 产业信号、L4 线索、L5 推论、L6 建议。
- 行动等级：Adopt / Trial / Assess / Hold / Blocked。
- 风险门：安全、license、供应链、隐私、合规、AI 评测、成本、维护和组织落地。
- 沉淀守卫：研究结果按 article / concept / template / project / decision / report / skill 路由，并补知识链接。

## 只能抽象吸收

- 外部工程的 13 个研究子项只能作为覆盖面参考；目标工程是否拆分子技能取决于真实高频需求。
- 调研文章、source matrix、benchmark、产品结论和项目案例只能作为方法样例。
- 目标工程已有研究模板、知识库或源码审计流程时，字段应映射到既有结构。

## 禁止复制

- 不复制源工程的路径、排行、分数、source revision、调研对象清单或一次性 log。
- 不复制具体技术选型、采购建议、项目阶段、业务场景、PoC 结果或外部公司事实。
- 不把没有当前查证或运行验证的外部研究结论写成生产接入、验收闭环或采购拍板。

## 目标工程结构自检

1. 是否已有 research / investigation / technical assessment / knowledge capture 能力？
2. 是否已有 `articles/`、`concepts/`、`docs/`、`projects/` 或等价知识沉淀层？
3. 是否已有调研模板、技术选型页、源码审计流程或 PoC 报告模板？
4. 哪些对象分支是真实高频，哪些只应保留在聚合 skill 中？
5. 是否有 sensor 能验证入口、模板字段、README 链接或知识回链？

## 验证要求

- 新技能必须在 README 或等价入口登记。
- 至少用一个技术概念、一个开源工程或一个 AI / 行业方向做干跑自检，确认不会越级结论。
- 如果目标工程有 sensor，接入统一检查；没有时至少检查 frontmatter、模板字段、入口链接和禁止项。
- 最终回复写清已更新文件、未迁移的项目事实、检查结果和未验证边界。
