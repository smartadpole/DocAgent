# Research Method Route Map

本文件是 [[skills/research-capability/SKILL]] 的方法储备，不是新的技能入口。它吸收 AcknowledgeBase 中更细的研究子项方法，但只保留可迁移的触发、证据、检查和输出边界；不复制外部项目事实、生活事实、报告排行、source revision 或历史记录。

## 使用边界

- 对外仍统一从 [[skills/research-capability/SKILL]] 进入。
- 子项只作为研究方法 lens；除非本仓出现稳定高频需求，否则不平铺成新的 `skills/*/SKILL.md`。
- 正式研究产物必须把外部原文、raw / source ledger、数据快照或社区深读入口放在读者可见的位置，不能只留在对话、浏览器历史或隐式脚注里。
- 缺少 L1 一手事实、当前性核验或本地验证时，结论只能写 `reported / inferred / blocked`，不能写强采用、强采购、强接入或生产可用。

## 深度等级

| 等级 | 适用场景 | 必备证据 | 不能上推 |
| --- | --- | --- | --- |
| R0 线索 | 用户只要快速判断、资料刚进入 inbox / raw | 来源、时间、访问边界、初步可信度 | 不给行动建议 |
| R1 桌面初筛 | 需要比较方向、形成候选清单或排除明显不合适项 | L1 / L2 优先、L3 信号、当前性检查 | 不给采购 / 接入结论 |
| R2 验证计划 | 准备 PoC、用户验证、运行验证或市场验证 | 验证目标、指标、样本、成功 / 退出条件 | 不写已验证完成 |
| R3 结构分析 | 需要系统性方案、机制解释、风险和替代方案 | 证据矩阵、反证、敏感性、风险门 | 不替代正式决策 |
| R4 尽调 / 接入 | 会影响投资、采购、合作、生产接入或长期承诺 | 数据室 / 官方材料、三角验证、红旗分级、人工确认边界 | 不替代法务、合规、安全或人工拍板 |

R2+ 共用同一套 strong template-kernel 运行合同，不因方法子项不同而省略：先过 `Source Plan checkpoint`，再用 `coverage matrix` 管关键问题、支持证据、反证和 blocked；收到补充材料时执行 `Evidence Delta Re-open`。证据或评价失败后写 `Revision Brief`、`Delta Source Plan` 和 next-run decision，不在各子项复制第二套流程。

## 子项路由

| 子项 | 典型问题 | 关键方法 | 输出重点 | 守卫 |
| --- | --- | --- | --- | --- |
| 技术调研路由 | 对象不清，可能是概念、开源、行业、PoC 或源码工程 | 先判对象、决策目标、证据等级、成熟度、风险门和落位 | 调研合同、分支路线、刷新触发 | 不直接铺完整报告 |
| 技术专题 | 原理、机制、生态、替代方案、场景和 PoC | 概念边界、机制图、生态扫描、替代对比、PoC 成功 / 退出条件 | 技术判断、适用 / 不适用场景、decision output | 不用热点代替成熟度 |
| 开源工程 | GitHub / Hugging Face 项目是否可用 | 项目画像、活跃度、license、供应链、运行验证、代码结构、集成成本 | Adopt / Trial / Assess / Hold、接入策略 | 未跑通不写生产可用 |
| 行业 / AI | 赛道、趋势、产品机会、公司群体 | 趋势、技术路线、产品应用、竞争格局、治理风险 | 机会 / 风险矩阵、观察清单 | 不把媒体热度当事实 |
| 问题拆解 | 目标太大或模糊，不知从哪开始 | MECE 议题树、初始假设、80/20、所需证据映射 | 可验证子问题和任务路线 | 不把拆解当结论 |
| 结构化判断 | 证据不全但必须裁决 | 竞争性假设、关键假设检验、敏感性分析、概率语言 | 置信度、替代解释、反证 | 不伪装确定性 |
| 市场 | TAM、目标客户、定价、需求验证 | TAM / SAM / SOM、STP、Conjoint / MaxDiff、Van Westendorp / Gabor-Granger | 市场规模、细分、价格和渠道假设 | 不用单一报告替代样本 |
| 用户 | 用户是谁，为什么用，哪里卡 | 招募、访谈、可用性测试、SUS / SEQ / HEART、亲和图 | 用户画像、旅程、机会点、严重度 | 不用自我想象代替用户证据 |
| 竞争情报 | 对手在做什么，下一步可能怎样 | KIT / KIQ、情报循环、招聘 / 专利 / 财报 / Win-Loss、War Game | battlecard、早期预警、盲点 | 只用合法合伦理来源 |
| 尽职调查 | 投资、并购、采购、合作、招聘前排雷 | 财务 / 法律 / 商业 / 技术 / 运营 / 合规矩阵、三角验证、KYC / AML / UBO、reference call | 红旗分级、deal-breaker、未读清单 | 不替代专业审查 |
| 科研方法 | 因果、机制、实验设计、证据可靠性 | 可证伪假设、RCT / 准实验 / 观察、PRISMA、GRADE、效度和偏倚 | 证据等级、可重复性、研究设计 | 不把相关写成因果 |
| 战略前瞻 | 5 到 20 年不确定性和押注 | STEEP / PESTEL、情景规划、Delphi、Backcasting、Three Horizons、Wild Cards | 命名情景、战略含义、选择权 | 不预测唯一未来 |
| 社会与政策 | 政策 / 项目是否有效，对谁有效 | RCT、DiD、断点回归、PSM、工具变量、理论变革、OECD-DAC | 影响评估、成本效益、意外后果 | 不忽视伦理和反身性 |
| 生活 / 现场决策 | 健康、旅行、采购、维权、家务等个人场景 | 个人约束、当前性核验、候选全集、红旗 / 停止条件、验收 / 投诉证据 | 贴合本人预算、时间、地点和风险承受力的建议 | 个人事实不进本库通用技能 |

## 输出加严项

正式研究资产至少补齐：

- `溯源入口`：外部原文索引、raw / source ledger、数据快照或社区深读入口。
- `反证面`：否定信号、失败案例、替代解释、不可复现信息和旧结论过期风险。
- `风险门`：deal-breaker、人工确认、合规 / 安全 / 法务 / 采购边界。
- `行动兑现`：owner、检查方式、完成口径、刷新触发和下一次复查条件。
- `评价闭环`：deterministic validator、独立 evaluator / 人工 reviewer、outcome 状态、Revision Brief 和 next-run decision。
