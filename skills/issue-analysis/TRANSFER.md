# Issue Analysis Transfer

## 能力目标

从已发生现象与证据冲突定位最窄可信原因并验证修复。 运行入口为 [[skills/issue-analysis/SKILL]]；条件参考随入口按触发迁移，不全量注入每次运行。

## 可以吸收

- 原始现象、期望、影响、候选原因和最小可区分验证；快诊不自动建任务树。
- 权威事实源、状态/计数单位、时间、ID归一；区分receipt与持久化、展示与实际状态。
- 跨工程调查按条件参考展开责任、授权、local/service-side/end-to-end验证及主控吸收。
- 正式Issue保留案件原貌，report承接单次测试，TASK承接修复；分析不自动关闭父项。

## 只能抽象吸收

需求、调度、服务、领域、持久化和展示映射目标架构；事项模型和handoff路径不照搬。

## 禁止复制

不复制来源工程身份、私有路径、项目状态、服务实例、业务数据、凭据、历史日志或一次性检查结论。源工程可访问不等于获准修改；目标已有规则和用户授权优先。迁移结果不冒充业务验收或外部评价完成。

## 目标工程结构自检

查找已有等价能力、当前owner、实际发现入口、允许写入范围和验证方法；优先复用，缺项按需要补齐。模板、reference和sensor只迁移当前能力真正消费的部分，不为形式完整预建目录。

## 验证要求

验证请求成功但后台未完成、计数单位不同、内部证据不可读三种边界；非默认参数需要证明实际效果，局部修复不外推总验收。 运行目标适用检查，说明真实变更、验证和未证明的范围；结构检查不能证明模型行为正确。
