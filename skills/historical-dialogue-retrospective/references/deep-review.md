# 深度历史复盘

仅用于明确的深度/完整历史复盘，或已界定的重复机制失守调查。基础证据地图在 [[skills/historical-dialogue-retrospective/SKILL]]。

## 目标与时间锚点

记录首轮目标、最终目标、用户纠偏序列与未撤销约束。限定对话时间窗、commit 区间和相关 owner，缺口再决定扩读。用户的新目标可以改变方向，但不能把后续结果反写成用户最初意图。

原始 session / rollout 纳入证据计划；只可读摘要、当前片段或整理记录时标注缺失，并限制过程性结论。memory 仅帮助定位历史偏好与路径；判断回到 session、文件、diff 或检查输出。标注证据时间点，避免用已修正页面证明当时行为。

## 重建关键工作链

围绕目标与后续纠偏解释：agent 当时如何理解目标、为什么选择某响应模式、读了什么、遗漏什么、做了哪些工具调用与修改、如何验证、如何表达完成与不足，以及后续是否返工。选决定性事件，不机械逐条重述日志。

可按下列视角定位原因，但仅保留有证据的项：

- 目标/路由：是否把用户任务替换为另一种交付或错误 owner。
- 读取/执行：是否漏必要证据、重复扩读、越权或预建结构。
- 验证：是否缺反例、边界值或真实 runtime，是否把局部结果上推。
- 沟通/沉淀/收尾：是否隐藏缺口、事实落错层、漏必要提交或混入无关内容。

为关键判断列反证和替代解释，区分 confirmed / likely / possible / blocked。用户纠偏是理解目标的重要证据，但不能单独证明未经验证的技术根因。

## 效率、抽象与行动

区分必要成本、可优化成本和返工损失；把“做得多”与目标贡献分开。上层抽象与举一反三要指出可迁移失败模式、同类触发面和最小改进，不扩大本轮写入权限、不默认扫描所有工程。

相关旧行动回检由复盘总入口承接。改进写入原 owner；只有证据支持才晋升为模板、skill、sensor 或规则。标准/深度档案按 [[skills/retrospective-capability/SKILL]] 落到年份目录并同步索引；尊重用户明确只分析、不落文件的范围。结论和真实缺口都保留，不以“完整”之名无限扩读。
