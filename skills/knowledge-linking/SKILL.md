# 知识关联技能

## 定位

本技能把“调研 -> 沉淀知识 -> 总结方案 -> 网状关联 -> 检查验证”收敛成一套可复用流程。

它不负责盲目自动生成语义链接。语义关系由 agent 基于上下文判断，sensor 只负责抓结构性漏项，例如缺少出链、非 `[[log]]` 入链、入口页或上位页回链。

## 触发场景

- 用户要求“沉淀知识”“做成参考”“新增概念”“新增文章”“总结方案”“调研后沉淀”。
- 用户追问新知识是否和既有知识库形成关联、是否能被别人学习使用。
- 新增或大改 `articles/`、`concepts/`、`indexes/`、治理页、模板页或技能页。
- 本轮发现知识页只靠最终回复或 `[[log]]` 被发现，缺少入口、上位概念或邻接关系。

## 边界

- 调研不是每轮都重做；但用户明确要求“调研”，或事实涉及外部工具、官方约定、近期变化、可花钱/花时间决策时，必须查证来源。
- `[[log]]` 是历史记录，不是知识入口。新增知识不能只靠 `[[log]]` 入链通过。
- 不为了通过检查而堆无意义链接；每条链接要说明上位、邻接、案例、规则、模板或技能关系。
- 技能只提供执行方法，不替代 [[knowledge-linking-rules]]、[[WORKFLOW]]、[[POLICY]] 或目标页面的单一信息源。

## 读取顺序

1. [[knowledge-linking-rules]]：确认最小关联标准和 sensor 边界。
2. [[README]]、[[INDEX]]：确认总入口和已有主题归属。
3. 目标层入口：`articles/README.md`、`concepts/README.md`、`governance/README.md`、`skills/README.md` 或相关项目入口。
4. 目标页的上位概念、邻接页面、同主题文章、相关规则 / 模板 / 技能。
5. 外部来源：当用户要求调研或事实需要验证时，优先官方文档、原始论文 / 文章、作者原文，再用二级材料辅助理解。

## 工作流

### 1. 判定沉淀模式

先判断本轮属于哪种模式：

- 快速补链：已有知识页缺入口或回链，只补关系和检查。
- 标准知识沉淀：用户给出稳定经验，需要新增或更新概念 / 文章 / 入口。
- 调研沉淀：需要先查外部资料，再形成摘要卡片、概念或方案。
- 机制升级：需要新增规则、模板、技能或 sensor。

### 2. 调研与内外校准

调研沉淀至少覆盖两面：

- 外部依据：官方文档、作者原文、方法论或标准资料。
- 内部历史：现有 `articles/`、`concepts/`、`governance/`、`skills/` 中是否已有相邻概念、旧规则、案例或冲突。

调研输出要区分：

- 已验证事实。
- 方法论启发。
- 对本库机制的设计推论。
- 仍未验证或不适用的边界。

### 3. 分层落位

按内容职责选择主落位：

- 原始资料或导出物：`raw/`、`inbox/`、`assets/`。
- 单篇材料摘要：`articles/`。
- 可复用概念、方法或实体：`concepts/`。
- 执行规则、路由或裁定：`governance/`。
- 可复用 agent 执行流程：`skills/`。
- 可复制页面骨架：`templates/`。
- 过程记录：`log.md`。

如果一个主题同时需要多个层级，先明确单一信息源：概念讲“是什么”，文章讲“这次材料得出什么”，规则讲“以后怎么判”，技能讲“agent 怎么执行”。

### 4. 建立关系画像

每个新增或大改知识页都要写出最小关系画像：

- 所属层级。
- 主入口。
- 上位概念或 owning page。
- 至少一个邻接页面。
- 是否需要反向回链。
- 是否需要 `log.md` 记录。
- 应跑的检查命令。

### 5. 写入和验证

最小验证：

```bash
python3 scripts/check_all.py --only knowledge-linking
```

如果改了规则、技能、模板、入口或检查脚本，再跑完整检查：

```bash
python3 scripts/check_all.py
```

如果改了 sensor，本轮至少做一次负向测试：临时构造应失败的孤岛页或缺字段样本，确认检查能失败；删除测试样本后再确认通过。

## 输出格式

最终回复优先说明：

1. 调研是否已做，使用了哪些来源。
2. 知识沉淀到了哪些主页面。
3. 关联关系怎样形成：入口、上位、邻接、反向回链。
4. 验证命令和结果。
5. 未覆盖或仍需人工判断的边界。

## 自检清单

- 是否把用户给出的经验变成了别人能读、能复用的页面，而不是只留在对话里。
- 是否有外部调研来源或明确说明为什么本轮不需要外部调研。
- 是否至少有一个上位链接和一个非 `[[log]]` 反向入口。
- 是否更新了对应入口页。
- 是否把规则、概念、文章、技能、模板的职责分开，避免复制正文。
- 是否运行 `python3 scripts/check_all.py --only knowledge-linking`。
- 如果改了机制或 sensor，是否跑完整检查并说明负向测试边界。
