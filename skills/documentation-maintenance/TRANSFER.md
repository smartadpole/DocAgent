# Documentation Maintenance Transfer

## 能力目标

让目标工程具备 diff 驱动的文档维护能力：识别代码、结构、规则或公开行为变化是否让文档过期、缺失或不准确，并保守产出报告或受控修正。

## 可以吸收

- 报告模式 / 编辑模式 / AGENTS 同步模式 / 规则模板同步模式。
- diff 读取和用户可见变化提取：API、CLI、配置、默认值、行为、目录、命令、agent 规则。
- 文档映射分类：Stale、Missing、Broken example、No changes needed。
- 保守修正原则：只改必要处、保留风格、跳过 generated 文件、优先更新已有页。
- AGENTS 层级同步：共享知识放最浅共同入口，模块规则放最近 owning 文件。
- 验证收尾：专项检查、diff check、入口同步、log 和提交。

## 只能抽象吸收

- 源工程的产品文档风格、Mintlify 组件、测试命令、docs nav、CI 规则只能作为方法参考。
- 目标工程应替换成自己的 docs 结构、generated 文件规则、lint / test 命令和 PR 流程。
- 如果目标工程不是代码仓库，也可把“diff”映射为规则、模板、目录或项目事实变化。

## 禁止复制

- 不复制源工程的目录路径、产品名、组件库、提交规则、生成脚本或文档示例。
- 不把自动生成文档当成可手改目标。
- 不把代码行为验证、测试通过或 PR review 结论写成文档维护技能的结果。

## 目标工程结构自检

迁移前检查：

1. 文档入口、导航、README 和 docs 目录在哪里。
2. 哪些文件是 generated 或禁止手改。
3. 是否有 AGENTS 层级、模块规则或 agent 技能目录。
4. 文档 lint、链接检查、代码块测试、CI 或本地检查命令是什么。
5. 是否需要先报告再编辑，还是允许自动修正。

## 验证要求

- 用一个小 diff 或本轮规则变更跑报告模式，确认不会制造无依据发现。
- 如果执行编辑，确认只改必要位置并跑目标工程文档检查。
- 检查 generated 文件未被修改。
- 最终回复写清发现、修改、检查结果和未覆盖边界。
