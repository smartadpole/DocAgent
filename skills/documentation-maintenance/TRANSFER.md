# Documentation Maintenance Transfer

## 能力目标

根据真实公开行为或入口变化，保守修正文档漂移。 运行入口为 [[skills/documentation-maintenance/SKILL]]；条件参考随入口按触发迁移，不全量注入每次运行。

## 可以吸收

- diff/事实驱动，区分stale、missing、重复owner、broken example和无需修改。
- 已授权任务中的必要文档同步直接完成；用户只要报告时不写入。
- Generated改源，thin adapter不复制正文，方案未裁决不伪装生效规则。
- 普通内部重排或提交动作本身不触发全库治理。

## 只能抽象吸收

文档风格、目录、generated标记、检查和提交方式采用目标约定；不复制产品组件或某工程CI。

## 禁止复制

不复制来源工程身份、私有路径、项目状态、服务实例、业务数据、凭据、历史日志或一次性检查结论。源工程可访问不等于获准修改；目标已有规则和用户授权优先。迁移结果不冒充业务验收或外部评价完成。

## 目标工程结构自检

查找已有等价能力、当前owner、实际发现入口、允许写入范围和验证方法；优先复用，缺项按需要补齐。模板、reference和sensor只迁移当前能力真正消费的部分，不为形式完整预建目录。

## 验证要求

用一个公开变化和一个内部重构验证影响判断；编辑时检查源文件、入口与链接，不能靠制造发现通过。 运行目标适用检查，说明真实变更、验证和未证明的范围；结构检查不能证明模型行为正确。
