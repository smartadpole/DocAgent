# Cross-Project Skill Adoption Prompt

## 定位

本技能把“某个工程已经沉淀好的能力”转换成可交给另一个工程 agent 执行的升级包。

它生成的是提示词，不是直接执行迁移。提示词必须带：

- 要升级的能力目标。
- 本机已沉淀资料路径。
- 哪些可复制、哪些只能抽象吸收、哪些禁止复制。
- 目标工程结构自检与落位要求。
- 文件、模板、skill、规则、sensor 和入口同步步骤。
- 检查、提交和最终回复要求。

## 适用场景

- 用户说“把某个技能 / 体系迁移到其他工程”。
- 用户要求生成一段提示词，让目标工程 agent 升级某项能力。
- 用户要求把复盘、Issue 分析、验收、代码基线审计、状态推演、服务台账、会议体系、Goal Contract 或 Harness 治理等能力扩散到别的工程。
- 用户指出“提示词里要附上已有知识、方案、模板、本机地址”。

## 边界

- 本技能默认只生成目标工程执行提示词，不直接修改目标工程。
- 不整库复制，不原样搬运项目事实、log 历史、运行 ID、服务实例、业务链路、一次性 handoff 或具体状态。
- 只抽象系统层信息：触发条件、事实源分层、定位方法、输出格式、模板字段、回写守卫、禁止项、验证方式和入口同步。
- 通用提示词场景不预读目标工程；只有用户要求定制提示词或直接执行迁移时，才读取目标工程入口结构。
- 如果用户明确要求“现在去目标工程执行”，再切换到对应工程上下文和执行模式。

## 读取顺序

1. 当前用户目标：要迁移哪个能力、目标工程是谁、只是生成提示词还是要执行迁移。
2. `skills/README.md`：确认技能层边界。
3. 源技能：
   - `skills/<skill-name>/SKILL.md`
   - 如果存在，读取 `skills/<skill-name>/TRANSFER.md`
4. 相关资料：
   - skill 中引用的 concept、template、governance、project 入口。
   - `templates/skill-transfer-manifest-template.md`，用于补全迁移字段。
5. 目标工程结构处理按模式分级：
   - **通用提示词**：不读取目标工程；提示词中必须要求目标工程 agent 自行读取本工程入口和结构后再决定落位。
   - **定制提示词**：如果用户指定目标工程并授权读取，可轻量读取目标工程 `README`、`AGENTS`、`docs/`、`projects/`、`skills/`、`templates/` 等入口，用来把落位建议写得更准。
   - **直接执行迁移**：如果用户明确要求当前 agent 去目标工程落地，必须进入目标工程上下文，先完成结构读取，再改文件。

如果源技能没有 `TRANSFER.md`，先根据 `SKILL.md` 和相关页面生成一次性提示词；同时建议补一个 `TRANSFER.md`，不要把完整提示词长期写死。

## 输出结构

最终给用户一段可直接复制的提示词，默认包含：

```markdown
请升级目标工程的 <能力名称> 体系。

## 背景和目标

## 参考资料
- <本机路径>

## 吸收边界
- 可以吸收：
- 只能抽象吸收：
- 禁止复制：

## 目标工程结构自检与落位

## 需要建立或更新的模块

## 技能 / 模板 / 规则 / sensor 接入要求

## 行动分流和单一信息源

## 验证和提交要求

## 最终回复要求
```

## 迁移包生成规则

### 1. 先识别能力类型

| 类型 | 重点 |
| --- | --- |
| 方法体系 | concept / docs 方法页、档案入口、模板 |
| 执行技能 | skill 触发、证据源、工作流、输出格式、禁止项 |
| 治理能力 | AGENTS / WORKFLOW / POLICY、ledger、sensor、模板 |
| 研发事项体系 | Gate / FP / EP / TASK、risk、issue、AP、report、验收和状态回写 |
| 运行能力 | service registry、部署、健康检查、报告和事故 |

### 2. 列资料路径，不只列提示词

资料路径至少分成：

- 核心 skill。
- 方法论 / concept。
- 模板。
- 规则 / workflow。
- 运行层入口或档案入口。
- 检查脚本或 sensor。

路径必须使用本机绝对路径，便于目标工程 agent 直接读取。

### 3. 写清吸收边界

每份提示词都要明确：

- `可以复制`：模板骨架、字段、章节、检查口径。
- `抽象吸收`：方法、流程、触发条件、证据分层、输出结构。
- `禁止复制`：项目事实、业务名、历史 log、运行 ID、服务路径、一次性状态和本工程特有 handoff。

### 4. 强制目标工程自检和自适配

不要假设目标工程一定有 `projects/`、`docs/`、`skills/` 或 `templates/`。

提示词必须要求目标 agent：

1. 先读取目标工程入口和结构。
2. 判断已有模块能否复用。
3. 没有对应结构时给出保守落位。
4. 更新目标工程自己的入口页和 agent 规则。
5. 跑目标工程已有检查。

生成通用提示词时，不要替目标工程预判目录；只给默认建议和结构自检要求。生成定制提示词或直接执行迁移时，才读取目标工程入口结构。

### 5. 不把提示词当长期主资产

完整提示词是按需生成物。长期主资产是：

- 源 skill 的 `SKILL.md`。
- 源 skill 的 `TRANSFER.md`。
- 相关 concept / template / governance 页面。
- 本 meta-skill。

## 输出前自检

- 是否明确了目标能力，而不只是文件落位。
- 是否包含本机资料路径。
- 是否区分方法论、档案 / 页面、模板、skill、规则和 sensor。
- 是否写清了 action sinks / 单一信息源。
- 是否禁止整库复制和项目事实搬运。
- 是否区分通用提示词、定制提示词和直接执行迁移。
- 是否要求目标工程自读结构、自适配落位、跑检查和提交。

## 禁止项

- 不生成只有“新建目录 / 新建模板”的片面提示词。
- 不遗漏源 skill 和相关模板 / concept / governance 路径。
- 不把 AcknowledgeBase 的具体项目事实当成目标工程事实。
- 不让目标工程 agent 跳过目标工程结构读取。
- 不在通用提示词生成阶段强行读取目标工程结构。
- 不要求目标工程照搬 AcknowledgeBase 的目录名；只能给默认建议和适配规则。
