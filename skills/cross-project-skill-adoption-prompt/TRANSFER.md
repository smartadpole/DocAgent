# Cross Project Skill Adoption Prompt Transfer

## 能力目标

在授权目标完成技能原生采纳，或在明确任务书模式生成可执行移交。 运行入口为 [[skills/cross-project-skill-adoption-prompt/SKILL]]；条件参考随入口按触发迁移，不全量注入每次运行。

## 可以吸收

- 区分直接执行、源能力维护和任务书交付；已明确目标及写入授权时不退回只生成提示词。
- 先检查目标规则、branch/dirty、allowed roots和已有等价能力，再修改实际owner与消费者、验证并按目标规则提交。
- 任务书细节按条件参考加载；golden baseline按语义和行为覆盖比较，不以篇幅或章节顺序裁定。
- 系统级/矩阵任务才加载对应分层、Matrix Recognition Capsule与external readback要求。

## 只能抽象吸收

源模块清单和风险来自实际能力；目标结构与验证命令由目标工程确定，不把单个样稿扩成所有迁移固定流程。

## 禁止复制

不复制来源工程身份、私有路径、项目状态、服务实例、业务数据、凭据、历史日志或一次性检查结论。源工程可访问不等于获准修改；目标已有规则和用户授权优先。迁移结果不冒充业务验收或外部评价完成。

## 目标工程结构自检

查找已有等价能力、当前owner、实际发现入口、允许写入范围和验证方法；优先复用，缺项按需要补齐。模板、reference和sensor只迁移当前能力真正消费的部分，不为形式完整预建目录。

## 验证要求

分别验证“已授权可写目标”和“只要提示词”两个场景；检查前者真实落地、后者不越权，均保留专业边界与未验证项。 运行目标适用检查，说明真实变更、验证和未证明的范围；结构检查不能证明模型行为正确。
