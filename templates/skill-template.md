# <Skill Name>

## 何时使用

说明输入信号、要解决的问题和预期成果；明确哪些相似任务不需要启用本技能。

## 最小工作流程

只保留能改变执行或判断的步骤、必要事实 owner、输入 / 输出约束和验证方式。已有 owner 中的目标、证据和状态用链接复用；按任务复杂度交付足够深的结果，不固定套用一整套“输入 / 分析 / 行动”或成熟度自述。

## 条件能力

仅当出现对应风险、对象、操作或证据缺口时启用专业步骤。较长能力可以放同目录条件文件，并在 frontmatter 的 `conditional_sources` 列出真实路径；正文必须写清触发条件和链接，不能要求每次全读所有扩展。

## 验证与迁移边界

- 记录实际验证方式和未覆盖边界；文档结构、sensor 通过与自述不能代替运行或模型行为证据。
- 技能只维护可复用流程、判断框架和写入守卫；项目事实引用正式 owner，不复制状态、服务实例、数据表、运行 ID 或一次性 handoff。
- 规则、状态、设计或验收口径变更回到对应 owner；技能结论不能替代正式测试报告、TASK / EP 状态或 Gate 准出；TODO 仅作轻量兼容视图。
- frontmatter 的 `maturity`、`evidence_signals`、`sensor` 按已有证据填写，不预填已成熟或已验收；没有可检查面时 `sensor: none`，无需重复自我评价章节。
- 只有写清跨工程吸收边界、目标自检和验证要求后才能设 `transfer_ready: true`；此时同目录必须有 `TRANSFER.md`，说明能力目标、可以吸收、只能抽象吸收、禁止复制、目标工程结构自检和验证要求。不能迁移源工程的私有事实或授权。
