# Skill Transfer Review Contract

本模板用于审核跨工程技能迁移任务书是否足够可执行。

## 审核表

| 项目 | 通过标准 | 失败处理 |
| --- | --- | --- |
| 源能力 | 有 SKILL、TRANSFER 或明确来源 | 先补源归一 |
| 目标入口 | 指定目标工程先读什么 | 补入口规则 |
| 吸收边界 | 可以 / 抽象 / 禁止分开 | 重写边界 |
| 结构自检 | 不预设目标目录 | 改成自检问题 |
| 模块字段 | 到 skill / template / governance / sensor 字段级 | 补字段 |
| 验证 | 有专项、总检查、手工回看 | 补验证 |
| 禁止项 | 明确不复制项目事实 | 补禁止项 |
| 最终回复 | 要求文件、检查、未吸收、commit | 补回复合同 |

## 迁移任务书不能缺的句子

- “先读取目标工程入口规则。”
- “只吸收可迁移方法，不复制源工程项目事实。”
- “目标工程已有同名能力时，优先差异合并。”
- “没有 sensor 框架时，先给人工自检。”
- “本任务书不代表目标工程已经完成迁移。”

## 审核结论

```markdown
任务书状态：ready / needs-work / blocked
主要缺口：
必须补：
可以后补：
不能吸收：
```

## 反模式库

### 反模式 1：整库同步

表现：任务书要求目标工程“照着源工程做一套”，没有区分源项目事实和系统层方法。

修正：把内容拆成触发条件、事实源、流程、输出、验证和禁止项；源项目路径、服务、数据和状态全部移出。

### 反模式 2：只给提示词，不给证据

表现：任务书只有“请完善某技能”，没有参考资料、落位要求和验证方式。

修正：补源 `SKILL.md`、`TRANSFER.md`、模板、治理页、sensor 和目标入口。

### 反模式 3：目标结构臆测

表现：直接要求目标工程创建某目录，忽略已有 AGENTS、skills 或 rules。

修正：先写结构自检，让目标 agent 查已有目录和最近 owning 规则。

### 反模式 4：成熟度分数复制

表现：把源工程矩阵分数写进目标工程，暗示目标工程也已经成熟。

修正：只迁移证据信号模型；目标工程必须用本地文件和 sensor 重新验证。

### 反模式 5：sensor 过度承诺

表现：sensor 检查字符串通过，就声称语义完成。

修正：sensor 只证明 wiring；最终还要人工回看触发、边界、输出和禁止项。

### 反模式 6：模板污染

表现：把某个主题的字段写成所有技能迁移的默认字段。

修正：模板只保留通用迁移字段，主题字段留在具体任务书。

### 反模式 7：回写越权

表现：用户只要求任务书，agent 直接改目标工程。

修正：明确“本轮只生成任务书”；除非用户授权，否则不进入目标工程执行。

### 反模式 8：未吸收内容不说明

表现：最终回复只说“已迁移”，没有说哪些项目事实被拒绝。

修正：最终回复必须列出未吸收内容及原因。

## 最小 ready 标准

任务书达到 ready 需要满足：

- 目标 agent 可以按顺序执行，不需要猜第一步。
- 每个新增文件类型都有职责说明。
- 每个禁止项都能防止一种真实误迁移。
- 每个验证命令都能在目标工程找到或有替代方案。
- 最终回复能区分已完成、未验证和不吸收。

如果只是“建议目标工程参考某技能”，状态是 needs-work。

## 最终回复清单

- 已生成的是任务书还是已执行迁移。
- 目标工程是否被修改。
- 源能力哪些内容被吸收。
- 哪些项目事实被拒绝。
- 目标工程需要跑哪些检查。
- 哪些检查本轮未跑。
- 是否产生 commit。

## 额外边界提示

- 任务书可以要求目标工程补 sensor，但不能声称 sensor 已存在。
- 任务书可以建议目标工程补 views，但不能假设目标工程需要 HTML。
- 任务书可以列出推荐路径，但必须允许目标工程按本地结构调整。
- 任务书可以携带源路径，但必须提醒目标 agent 只作只读参考。
- 任务书可以描述成熟度缺口，但不能把缺口修复结果预先写成完成。
- 任务书可以要求提交，但最终是否提交服从目标工程规则。
- 任务书可以要求 log，但目标工程没有 log 时要使用等价记录入口。

## 完成判定

- `taskbook-ready`：任务书可直接交给目标 agent。
- `source-needs-normalization`：源能力还缺 TRANSFER、模板或治理边界。
- `target-needs-discovery`：目标工程结构未知，需要先读入口。
- `blocked`：用户未授权、路径不可读或关键材料缺失。

`taskbook-ready` 也不等于目标工程完成迁移；它只说明任务书足够交给目标 agent 执行。
目标工程完成迁移必须由目标工程自己的文件、检查、提交和最终回复证明。
