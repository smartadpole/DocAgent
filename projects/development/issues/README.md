# ISSUE 问题索引

> ISSUE 是已经发生或已复现的问题事实，通常来自验收失败、复验失败、线上现象、事故、实施偏差或子工程 bug。每个 ISSUE 必须一事一页；本页只做导航、摘要和状态扫描。

## Issue 与报告分工

一句话：Issue 是案件档案，报告是每次庭审记录。Issue 要收口，报告要按轮次和证据边界分开。

- **Issue / 案件档案**：一个已发生问题只保留一个主档案页，收口原始现象、当前状态、主责和协同方、根因边界、关闭标准、最新有效结论、未闭合缺口和报告链。
- **报告 / 庭审记录**：每次验收、复验、补测、部署验证、现场失败、关闭争议或证据边界变化，都进入独立测试报告。报告只证明本轮验收对象、样本、环境、命令、证据和结论。
- **一案多审**：同一个 ISSUE 可以有多份报告，但不因此拆成多个 ISSUE。新报告改变状态、owner、关闭标准、根因边界或未验证项时，必须回写 issue 档案页和本索引。
- **关闭读取顺序**：先读 issue 档案页的当前结论和最新有效报告，再沿报告链回看历轮证据。旧报告保留为证据链；若后续报告推翻或覆盖旧结论，只标注覆盖关系。
- **latest valid report**：对应中文字段是“最新有效报告”，用于标记当前关闭裁决真正采用的最后一份有效验证证据。

## 创建边界

- 功能尚未实现、尚未验收或只是识别到风险时，不创建 ISSUE，只在 risk、TASK / EP 或关系矩阵里记录 `issue-trigger:`。
- 只有 bug、实施偏差、事故、复验失败或验收失败已经发生后，才创建或复用 ISSUE。
- ISSUE 不是 RISK：ISSUE 记录已发生的问题事实，RISK 记录可能影响目标达成的风险评估和缓解计划。

## 维护规则

- 新 ISSUE 默认复制 [[templates/development-issue-template]]。
- ISSUE 必须维护原始现象保真：先保留用户原始报告的触发动作、入口和表面现象，再写直接观察、辅助证据和候选根因。
- ISSUE 必须写清关联 EP / TASK / FP / risk / Bug ID、最新有效报告、关闭标准和回归守卫。
- 新增或更新 ISSUE 时，先改实体页，再同步本索引摘要；不要把复现、根因、证据和沟通包写在索引页里。
