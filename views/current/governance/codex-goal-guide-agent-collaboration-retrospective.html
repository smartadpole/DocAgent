这页不重新讲 Goal 怎么用，而是回答一个更窄的问题：为什么一个公开教程产物需要多轮用户纠偏才收敛，以及下次 agent 应该提前看见哪些断点。

生成：2026-06-12 17:38 源版本：0a08d8e 主源：复盘档案 证据边界：confirmed / likely / blocked
一眼判断 问题不在工具执行，而在公开产物的前置合同。

HTML 导出、检查、提交都能稳定闭环；真正拉长对话的是首轮没有同时冻结受众、案例入口、公开措辞、版本策略和重定向触发。

背景框

上位背景

AcknowledgeBase 的 Agent 工作复盘，聚焦公开教程、图文 lens 和长对话协作成本。

来源背景

已读复盘档案、复盘入口、log、views 入口和 lens registry；未读完整原始 session。

关系背景

关联公开 Markdown 教程、通用版 HTML、工程事项版 HTML、harness ledger 和项目记忆。

使用边界

这是呈现层 lens，不替代复盘真相源，也不把单次问题直接升级成硬规则或 sensor。

收敛时间线

公开教程

先完成结构化教程，但更像方法论说明，案例叙事不足。

初版 HTML

页面可以呈现核心点，但首屏口吻偏纠偏提醒，不够专业。

文案修订

用户指出目标偏移和多余信息后，才收窄为正向定义。

案例入口

报告页导出闭环被放到首屏，读者终于有真实开发代入点。

公开措辞

“脱敏开发案例”等处理痕迹曾进入展示文案，后续被移除。

第二版本

EP -> TASK -> ISSUE -> REPORT 成为工程治理受众的独立版本。

证据边界

confirmed

  • 复盘源页已经记录目标、结果、偏差、行动和边界。
  • log 已记录公开教程、HTML 修订、案例化和第二版过程。
  • views 层已有两版 Goal 教程 HTML。

likely

  • 用户协作风格观察适用于本库 agent 协作，但不是全局人格标签。
  • 多版本策略缺失是收敛慢的重要原因之一。

possible

  • public-copy lint 可以脚本化，但需要先评估误报和白名单。
  • 公开教程分支可并入图文技能，也可能发展成更窄技能。

blocked

  • 未读取完整原始 rollout，不能逐条还原所有 tool call。
  • 未抽样所有历史公开产物，不能证明这是全局重复问题。
