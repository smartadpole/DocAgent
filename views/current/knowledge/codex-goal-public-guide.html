Codex Goal 使用教程

Codex Goal：对准可验证结果

适用于迁移、重构、性能优化等需要多轮推进的工作。启动前明确目标状态、验证循环和停止边界。

Goal = 目标状态 + 验证循环 + 停止边界 目标定义结果，验证循环衡量进展；停止条件让 Codex 在证据不足、权限受限或需要人工裁决时暂停。
验证
驱动

定义目标状态

目标要比一次 prompt 更持久，但比开放 backlog 更聚焦。先写清最终应达到的可观察状态。

建立验证循环

指定测试、benchmark、构建、截图、报告或 artifact。没有验证循环，Goal 就缺少完成标准。

设定停止边界

当权限不足、验证失败、预算耗尽或需要人工判断时，Codex 应暂停并说明当前缺口。

可复制公式

/goal 达成 <目标状态>，并用 <测试 / benchmark / artifact> 持续验证。保持 <约束>，只在 <允许范围> 内修改；若出现 <停止条件>，暂停并报告已有证据、剩余缺口和所需输入。

适合

  • 迁移、重构、性能优化、flaky test 定位。
  • 结果清楚，并且能通过测试、指标或产物验证。
  • 需要 Codex 跨多轮保持同一个完成标准。

不适合

  • 目标只有“继续完善”“优化一下”等模糊表达。
  • 把日志、启动成功或局部通过当作完成证据。
  • 缺少暂停、升级或人工裁决条件。
