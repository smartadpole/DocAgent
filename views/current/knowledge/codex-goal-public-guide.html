Codex Goal 使用教程

别把 Goal 当自动跑按钮。

对外发布时只要突出这一点：Goal 的核心是让 Codex 围绕一个可验证停止条件持续推进。

Goal = 目标 + 证据 + 停止条件 目标告诉 Codex 要去哪里；证据告诉它是否到达；停止条件告诉它什么时候必须停下来汇报。
可验证
停止

写清一个目标

任务要比一次 prompt 大，但比开放 backlog 小。用一句话说清最终要达成的状态。

绑定验证证据

指定测试、benchmark、构建、截图、报告或 artifact。没有证据，Goal 就没有完成标准。

设定停止条件

权限不足、证据不足、预算耗尽或需要人类裁决时，Codex 应暂停并说明缺口。

可复制公式

/goal 完成 <明确目标>，直到 <可验证完成状态>。使用 <测试 / benchmark / artifact> 检查进展，保持 <约束>，只在 <允许范围> 内修改。若出现 <停止条件>，暂停并报告已有证据、缺口和需要的输入。

适合

  • 迁移、重构、性能优化、flaky test 调查。
  • 有清楚目标、验证循环和可持续推进空间。
  • 需要 Codex 跨多轮保持同一个完成标准。

避免

  • “继续完善”这类没有终点线的 goal。
  • 把日志、启动成功或局部通过误当完成。
  • 没有停止条件，导致任务无限扩散。
